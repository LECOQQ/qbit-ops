# qbit-ops demo environment

A disposable, synthetic qBittorrent instance for taking safe screenshots
and terminal recordings of the qbit-ops TUI. No real qBittorrent
instance, private tracker, or downloaded media is ever involved.

## Prerequisites

- Docker with the `compose` plugin
- Poetry (`make install` already sets up the project)
- [VHS](https://github.com/charmbracelet/vhs) — optional, only for `make demo-record`

## Usage

```bash
make demo-up      # generate fixtures, start qBittorrent, seed torrents
make demo-tui      # launch the TUI against the demo instance only
make demo-record   # record demo/tui.tape with VHS
make demo-reset    # wipe and recreate the exact same demo inventory
make demo-down     # stop and remove all demo containers, network, state
```

## Isolation

- WebUI bound to `127.0.0.1:18080` only, never a LAN-reachable address.
- `qbit-ops` is pointed at `demo/qbit-ops.env` explicitly (`QBIT_OPS_ENV_FILE`) —
  the repository `.env` and `~/.config/qbit-ops/.env` are never read.
- Fixed demo-only credentials (`demo` / `demo-only`); no real qBittorrent
  instance, private tracker, or passkey is ever contacted.
- DHT, PeX, LSD, and UPnP/NAT-PMP are disabled inside qBittorrent from
  first boot. The Docker network itself still permits outbound egress —
  only qBittorrent's own peer-discovery features are turned off.
- All 16 torrents are synthetic, trackerless, and built from
  locally generated bytes — nothing is downloaded.

## Recording output

`make demo-record` writes `demo/output/qbit-ops-demo.gif` (gitignored).
Review it before publishing — it is not copied into the README automatically.

## Troubleshooting

- **`make demo-up` hangs waiting for the WebUI**: check `docker logs qbit-ops-demo`.
- **Stale state after edits to `fixtures.toml`**: run `make demo-reset`.
- **`make demo-record` fails with "vhs not found"**: install VHS separately;
  it is never a Python dependency of this project.
